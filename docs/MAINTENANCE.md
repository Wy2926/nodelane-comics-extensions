# 插件维护与发布

## 目录与职责

`src/<slug>/manifest.json` 声明来源及构建文件，本站协议留在同一目录。`test/` 使用合成数据与真实 App 的契约样本。`scripts/` 提供构建、校验、本地发布、恢复与开发服务器。`.build/` 是可重建的暂存输出，`repo/` 是供 App 下载的发布内容，二者不混用。

本仓库没有 App／浏览器项目的目录依赖；移植代码须记录固定版本、摘要与许可。只有多个实际站点证明相同实现可复用时才提取共享模块，并在构建时打包到站点插件；不在运行时下载共享代码。不复制全站点列表作为“已支持”名单。

## 新增和修复

```sh
npm run new-source -- example 86001003 https://example.org Example
```

生成的插件默认 `enabled: false`，不进入目录。填好本站协议、范围说明与样本测试，通过后再启用。永久 ID 只分配一次；改名、换域名、换目录渠道或发布版本不改变 ID，移除站点也保留 `repository.json` 分配记录。`repo/registry.json` 保存已发布的分配，构建拒绝删除或重分配。仓库固定身份为 `net.nodelane.extensions`。

新增来源至少覆盖热门／搜索、空结果、分页、章节归属、重复条目、图片顺序、服务器错误与验证页；修复须有能够复现故障的用例，优先补充现有回归测试，避免重复测试同一行为。目录只交付可靠完整快照，不能用失败、被截断的页面或验证码页面代替空结果。保留原上传、0 话、小数话与必要查询参数；不按作品名称推断身份。

目录去重使用规范化后的完整章节 URL，去重前仍核对每条记录的归属；相同名称或编号的不同 URL 不能合并。不要只验证一部作品：站点修复先把已发现变体转成合成样本，再用有上限的热门／最新抽样检查覆盖面。诊断错误细分地址格式、作品归属、目录完整性、图片清单与源站空正文，不能都归为“页面结构变化”。

`npm run build` 按 `manifest.files` 生成单文件 JavaScript 和摘要索引。清单检查永久 ID、版本、路径、主机、声明能力和产物大小，执行 JavaScript 语法检查。代码在 `.build/` 内可反复改动；一旦发布到 `repo/packages/<slug>/<version>.js`，同版本不可覆盖。

## 验证

```sh
npm run check
npm run test:app -- /明确选择的路径/nodelane-comics-app
```

普通 CI 只依赖本仓库与 Node。`test:app` 是显式的跨仓库兼容检查：调用所选 App 的 Flutter 工具，将本次 `.build` 和 `test/fixtures/contracts.json` 交给通用 QuickJS 测试入口；App 的普通测试和运行都不读取本仓库。新增接口样本应加入该契约文件，不在 App 测试中添加网站分支。

Node DOM 样本使用 LinkeDOM，实际 App 使用自己的 DOM 桥，两者均须验证。真实站点检查单独执行，避免站点波动或 CAPTCHA 让每次离线 CI 不可用。真实检查低并发、有数量与大小限制，只输出计数、错误和已脱敏诊断；不保存 Cookie、请求签名和图片签名地址。图片样本与截图只放忽略的 `artifacts/`。

模拟器验收覆盖来源刷新、按需安装／更新、搜索与详情、章节首尾页、后台恢复和进度保持；真机、真实 CF 验证、翻译服务单独验收。Android 暂缓。不能用 Node 请求成功代替 App WebView／阅读器验收。

## 发布和恢复

```sh
npm run release -- testing
# 完成目标平台验收后，才推广同一构建：
npm run release -- stable
```

发布先构建并运行离线测试，再校验整个批次，写入不可变版本文件、对应源码和许可，最后原子替换该渠道的索引。发布锁阻止并发写入；重复发布同一内容可重入。原子落盘避免中断留下半份活动文件。进程中断留下 `.publish-lock` 时，先核实发布进程已经结束，再移除锁并重新执行；保留已完成的版本文件。

正式与测试渠道具有独立索引。旧 App 仍使用根目录索引作为本地测试入口；切换正式地址由 App 构建配置显式指定。HTTP 仅用于本机或局域网开发，远程必须 HTTPS。版本产物可长期缓存，索引使用重新验证策略；静态服务不代理源站或接收设备 Cookie。

来源更新时 App 校验元数据、同源下载地址、文件大小和 SHA-256，初始化成功才保存；失败保留旧代码、来源 ID、固定状态与书架关系。站点改版导致已经安装的新插件运行故障时，用更高版本重新发布归档实现：

```sh
npm run rollback -- comix 0.2.0 0.2.2 testing
```

恢复命令核验归档产物及源码可重现性，保留其他插件和工作区源码，不通过降低索引版本假装回滚。恢复后同步修复工作区版本，避免后续发布被降版检查拒绝。每个已发布版本的 `sources/<slug>/<version>/rebuild.mjs` 可独立重建 `plugin.js`。

## 正式托管前的边界

本地 Git 仓库与测试源已经独立，公开仓库为 `Wy2926/nodelane-comics-extensions`；永久仓库身份 `net.nodelane.extensions` 不随 GitHub 仓库名改变。正式分发域名、托管和发布密钥尚未配置。SHA-256 校验发现内容错配，不能证明发布者；面向用户的正式分发还需要签名索引、App 固定验证公钥和密钥轮换流程。正式上线前核对源码与许可证随包提供方式，不把现有 Apache-2.0 App 基线与 GPL 插件混为同一许可。

故障报告至少带来源名／版本、App／iOS 版本、失败步骤、可公开作品或章节链接、错误类型。区分 CF、站点验证码、限流、网络失败、协议变化和不支持的图片；不要提交认证信息或完整请求日志。
